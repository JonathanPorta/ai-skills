# PRD: Bootstrap Skill Repository

## Summary

Establish `ai-skills` as a portable collection of reusable Agent Skills, beginning with the existing `package-design-handoff` skill and a dependency-free validation workflow.

## Codebase Analysis

### Explored

- `README.md` — Contains only the repository title.
- `.ai-rules/AGENTS.md` and referenced core rules — Require documented acceptance criteria, validation-first implementation, a Makefile command surface, and phase-gate auditing.
- `CLAUDE.md` and `.github/copilot-instructions.md` — Delegate agent behavior to `.ai-rules` and contain no collection-specific conventions.
- Installed `package-design-handoff` skill — Contains `SKILL.md`, OpenAI interface metadata, an icon, and a standard-library Python packaging helper.

### Relevant Patterns

- Skills use one directory per skill with `SKILL.md` as the required manifest.
- Optional skill resources use `agents/`, `assets/`, `references/`, and `scripts/` directories.
- Repository branch and commit conventions use Jonathan's initials and Conventional Commit prefixes.

### Constraints Discovered

- The repository has no Makefile, test suite, or root validation command.
- Agent Skills package-manifest proposals remain unsettled, so a custom root manifest would create premature coupling.
- The repository is currently public even though the intended long-term visibility is private; visibility is not changed by this feature.

### Owner-Confirmed Requirements

- Use `skills/<skill-name>/` rather than an `all/` directory or agent-specific copies.
- Add human-facing documentation inside each skill when its installation or usage needs explanation.
- Prefer installation by symlinking from a reviewed local checkout.
- Support Open Design as well as Codex/OpenAI harnesses.

### Implementation Choices Awaiting Owner Acceptance

- Keep harness-specific metadata beside the skill it describes.
- Defer a collection-level package manifest until its distribution contract is clear.
- Describe compatibility only at the exact harness revisions exercised by tests.

These are reviewable choices in this PR. They are not recorded as prior human
ratification, and final PR approval remains the owner-acceptance event.

## Background

The collection currently has AI workflow rules but no canonical skills. The first skill already exists and has been validated in its installed form; this feature makes a reviewable repository copy, documents collection conventions, and adds repeatable checks that future skills must pass.

## Goals

- Publish the first canonical skill at `skills/package-design-handoff/`.
- Explain repository structure, installation, compatibility status, contribution steps, and manifest policy.
- Make the first skill natively discoverable by Open Design and document symlink-based installation for Open Design and Codex.
- Provide dependency-free `make test` and `make check` workflows that validate schemas and resources and exercise security, publication, and packaging behavior.

## Non-Goals

- Introduce `skills.json`, `package.json`, a lockfile, or a custom package format.
- Add an `open-design.json` marketplace sidecar before the skill needs a marketplace listing.
- Duplicate each skill into harness-specific top-level directories.
- Change repository visibility or configure releases and distribution infrastructure.
- Modify the behavior of the already-installed personal skill.

## Architecture & Approach

- Store every reusable skill immediately below `skills/`.
- Copy the validated `package-design-handoff` skill and add a skill-local behavior and installation guide.
- Keep strict standard Agent Skills frontmatter and exercise it through pinned Open Design's production discovery and staging path.
- Add `scripts/check_skills.py` for strict YAML schema, field-limit, asset, executable, text, and source validation.
- Add repository-level `unittest` coverage for credential boundaries, portable ZIP namespaces, atomic publication, and the packaging helper.
- Ignore Python bytecode generated by repository-level validation.
- Expose validation through `Makefile` and document only that canonical command in the README.

## Acceptance Criteria

Implementation evidence is complete for each criterion below. Owner acceptance
is intentionally pending until the pull request is approved.

- AC-1: `skills/package-design-handoff/` contains a valid `SKILL.md`, OpenAI interface metadata, icon asset, and executable packaging helper.
- AC-2: The root README explains the collection purpose, `skills/<name>/` layout, current compatibility status, symlink-first installation, contribution steps, and the current manifest decision without claiming prior ratification.
- AC-3: `make help` lists `test`, `check`, and pinned integration surfaces; `make check` exits zero using only Python's standard library plus GNU Make.
- AC-4: Automated validation proves initial and incremental SemVer packaging, current-series archive exclusion, unrelated ZIP retention, dependency-tree exclusion, handoff metadata, and non-monotonic-version rejection.
- AC-5: The skill-local README documents symlink-based Open Design and Codex installation and only CLI commands supported by pinned Open Design commit `517f39acde402c1a7af2189167a8d6957a3dac71`.
- AC-6: Credential-like content fails closed without exact-path review; ignore controls and payload reads never follow symlinks; portable ZIP namespace collisions are rejected.
- AC-7: ZIP validation and fsync happen privately before atomic no-clobber publication; failed validation or publication cannot delete a competing destination or expose a partial fallback.
- AC-8: The validator parses actual Agent Skills and OpenAI YAML, enforces schemas and field limits, validates assets, and scans or rejects every executable/text resource.
